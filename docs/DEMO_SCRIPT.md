# Demo storyline (30 minutes, one accident)

The presenter drives it from the stepper at the top (keys 1 to 5 also jump; Shift+R resets).
Open the dashboard in a second window with `/?view=claims` (it syncs live with the main window).

| Step | Min | Screen | What happens | Proof point |
| --- | --- | --- | --- | --- |
| 1 | 3 | Platform stand-in (extras lane) | Issue a policy; a card number is allocated; a short-code simulator verifies it | We start from what they already run |
| 2 | 7 | Incident reporter on a phone (reporter lane) | Enter the card number (checked live), pick the crossing, add parties, injuries, photos; submit; reference and SMS preview appear | A report takes minutes, from any phone |
| 3 | 5 | Claims dashboard stand-in (claims lane) | The new claim appears as Notified within seconds; handling and issuing bureau handshake shows; the insurer's turnaround clock starts | It feeds their dashboard, not a parallel one |
| 4 | 8 | Compliance console (compliance lane) | Compliance reads 93.4% against the 90 to 95% band; open the exception list by insurer and channel; clear gaps with back-fill and reminders; the figure climbs; download the NAICOM return | The last 5% is visible and closable |
| 5 | 7 | Close | What we need from the operators, the pilot corridor (proposed: Nigeria to Benin through Seme), the working group | A clear next step |

Step 3 can switch to the operators' own deployed claims demo if they prefer. Our dashboard is a labelled stand-in.
